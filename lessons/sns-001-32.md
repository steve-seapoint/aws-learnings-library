# Adding an SNS Topic Policy Silently Disables Implicit Same-Account Publish

**Problem:** A CloudWatch alarm was set to notify an SNS topic (with a confirmed email subscription), but firing the alarm delivered no email. `aws cloudwatch describe-alarm-history --alarm-name <name> --history-item-type Action` showed `actionState: Failed` with `error: ... is not authorized to perform: SNS:Publish on resource: <topic-arn>`. Nothing about the alarm had changed — the only recent change was an unrelated EventBridge rule added to target the same topic.

**Root Cause:** SNS applies its permissive *default* access policy (which lets the owning account publish) **only while a topic has no explicit resource policy**. The moment any resource-based statement is attached — for example, an EventBridge target (CDK's `aws_events_targets.SnsTopic`) auto-adds a statement granting `events.amazonaws.com` publish — SNS enforces *only* what the policy says. CloudWatch alarm actions relied on the implicit same-account grant and have no statement of their own, so they are now denied. The failure is silent: the alarm still changes state; only the notification action fails, so it looks healthy from the alarm state alone.

**Solution:** Once a topic has any resource policy, grant every publisher explicitly. In CDK, grant the CloudWatch service principal:
```python
topic.grant_publish(iam.ServicePrincipal("cloudwatch.amazonaws.com"))
```
Or as a raw policy statement (repeat for any other publisher — Lambda, S3 events, etc.), scoped to avoid the confused-deputy problem:
```json
{
  "Effect": "Allow",
  "Principal": { "Service": "cloudwatch.amazonaws.com" },
  "Action": "sns:Publish",
  "Resource": "arn:aws:sns:REGION:ACCOUNT_ID:my-topic",
  "Condition": { "StringEquals": { "aws:SourceAccount": "ACCOUNT_ID" } }
}
```
Diagnose this class of failure with `describe-alarm-history --history-item-type Action`: a notification that never arrives while the alarm itself works points straight at a denied publish action.

**Key Insight:** Attaching *any* resource policy to an SNS topic revokes the implicit same-account publish grant for *every* service that was relying on it — so add explicit publish grants for all publishers the moment you add the first policy statement.
