# ApplicationLoadBalancedFargateService Opens the ALB to 0.0.0.0/0 by Default

**Problem:** A Fargate service deployed with the CDK `ecs_patterns.ApplicationLoadBalancedFargateService` L3 construct was reachable by anyone on the internet — data endpoints returned `200` to anonymous callers and opportunistic scanner bots were probing the public DNS name — even though public access was never intended and the application had no authentication yet.

**Root Cause:** `ApplicationLoadBalancedFargateService` (and its EC2 sibling) default `open_listener=True`. Combined with `public_load_balancer=True`, that silently adds an ingress rule to the load balancer's security group allowing `0.0.0.0/0` on the listener port. Nothing in `cdk synth` warns about it. The construct optimizes for "it works out of the box," not "it's closed by default" — so if the app's authorization isn't built yet, the entire service is exposed to the world the moment it deploys.

**Solution:** Set `open_listener=False` so the pattern does **not** add the world-open rule, then add ingress only for the CIDRs (or managed prefix list) that should reach it. An empty allowlist then means zero inbound — fail closed.

```python
service = ecs_patterns.ApplicationLoadBalancedFargateService(
    self, "ApiService",
    cluster=cluster,
    public_load_balancer=True,
    open_listener=False,           # do NOT add the default 0.0.0.0/0 rule
    task_image_options=...,
)

# Add an explicit client allowlist (from context, not hardcoded):
#   cdk deploy MyStack -c allowed_cidrs=203.0.113.10/32,198.51.100.0/24
for cidr in allowed_cidrs:
    service.load_balancer.connections.allow_from(
        ec2.Peer.ipv4(cidr), ec2.Port.tcp(80), f"allowlisted {cidr}"
    )

# If the ALB is fronted by CloudFront, allow only CloudFront instead of the world:
#   ec2.Peer.prefix_list("pl-...")  # com.amazonaws.global.cloudfront.origin-facing
```

**Key Insight:** Treat `public_load_balancer=True` as "open to the entire internet" unless you explicitly set `open_listener=False` and control ingress yourself — and never rely on unbuilt application-layer auth to protect an internet-facing service. (Bonus, learned the same day: turn on ALB access logs *before* exposure, and use an SSE-S3 (AES256) bucket — ALB access logging silently fails against an SSE-KMS bucket — so "who accessed this?" is answerable after the fact.)
