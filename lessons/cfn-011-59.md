# Signal a Wait Condition With curl When cfn-signal Is Missing

**Problem:** The boot script's first step installs `aws-cfn-bootstrap`, and that step fails (repo unreachable, slow mirror). The exit trap calls `/opt/aws/bin/cfn-signal`, which doesn't exist, so no signal is sent. The deploy sits at `CREATE_IN_PROGRESS` for the wait condition's full timeout, then fails with `WaitCondition timed out. Received 0 conditions when expecting 1` and no reason.

**Root Cause:** `cfn-signal` is only a convenience wrapper. The `WaitConditionHandle` is a presigned S3 PUT URL, and a signal is just a JSON document uploaded to it. Two details trip up a hand-rolled `curl`:
- The URL is signed without a content type. `curl --data` adds `Content-Type: application/x-www-form-urlencoded`, and S3 rejects the request with `403 SignatureDoesNotMatch`. Send an empty `Content-Type:` header.
- S3 accepts any bytes. If the JSON is invalid (an unescaped quote in the reason), the PUT succeeds but CloudFormation can't parse the signal, and the wait times out as if nothing were sent.

**Solution:** Try `cfn-signal` first and fall back to `curl` on any failure, including "command not found":

```bash
json_str() {  # JSON string literal without jq or python
  local s=${1//\\/\\\\}; s=${s//\"/\\\"}; s=${s//[[:cntrl:]]/ }
  printf '"%s"' "$s"
}
put_signal() {
  local status=SUCCESS body
  [ "$1" -eq 0 ] || status=FAILURE
  body="{\"Status\":\"$status\",\"Reason\":$(json_str "${failed:-ok}")"
  body+=",\"UniqueId\":$(json_str "$INSTANCE_ID"),\"Data\":$(json_str "exit $1")}"
  curl -sSf -m 30 --retry 3 -X PUT -H 'Content-Type:' --data-binary "$body" "$HANDLE_URL"
}
signal() {
  /opt/aws/bin/cfn-signal -e "$1" --reason "${failed:-ok}" "$HANDLE_URL" || put_signal "$1"
}
trap 'r=$?; signal $r || :; exit $r' EXIT
```

Use the instance ID as `UniqueId` (from IMDSv2), which is also `cfn-signal`'s default on EC2. If both senders fire, the second signal replaces the first instead of counting twice.

Test it without an instance: run the script's preamble in bash with a fake `curl` earlier on `PATH` that records its arguments, end with a failing command, and parse the recorded body with a real JSON parser.

**Key Insight:** The signalling tool can be the thing that failed to install. A wait condition signal is just an HTTP PUT, so keep a fallback that needs nothing but `curl`.
